Rencana Pembayaran Pulangin Air

Semua kemungkinan + saran + alur. Status: November 2026. Dokumen ini bilingual secukupnya; istilah teknis Inggris dipertahankan.

1. Posisi sekarang (fakta)

  • Kode yang live: Xendit (invoice + webhook token). Key asli belum tentu ada.
  • Kode Midtrans (Snap + webhook signature): ada di branch lain, belum live, belum ada key. Whitelist IP webhook Midtrans belum ada di kode mana pun (masih rencana).
  • QRIS statis GoPay merchant tersedia (a.n. Fainta Susilo Negoro) + tombol donasi sedang di-hide.
  • Pembeli belum dapat poin apa pun hari ini.

2. Semua kemungkinan

Opsi A — Midtrans penuh (tunggu ACC) menunggu kunci

Otomatis 100%: Snap → webhook → lunas. Butuh server key + dashboard config + webhook URL terdaftar. Tidak bisa jalan sebelum ACC turun.

Opsi B — Transfer manual + verifikasi admin rekomendasi — jalan besok

Pembeli transfer ke QRIS/rekening + klik "Saya sudah bayar" (+ bukti opsional). Admin cocokkan mutasi → Setujui → order terbuka. Tanpa kunci, tanpa fee gateway, tanpa integrasi.

Opsi C — Hibrida (B sekarang, A menyusul) rekomendasi arsitektur

Satu "jalur sukses" yang sama untuk dua pemicu (klik admin / webhook Midtrans). Efeknya identik: status lunas + poin + notifikasi + kwitansi. Saat ACC turun, yang diganti hanya pemicunya.

Opsi D — GoPay merchant API semi-otomatis syarat: cek akses API

Server menarik riwayat mutasi GoPay sendiri → sodorkan kandidat cocok ke admin → admin klik Setujui. Tetap butuh kredensial merchant + riset API.

Opsi E — Xendit sementara tidak disarankan

Bongkar-pasang dua kali, key belum pasti asli, dan arah sudah ditetapkan ke Midtrans. Buang waktu.

3. Pencocokan tanpa kode unik — paket yang disarankan

  • Tombol "Saya sudah bayar" + upload bukti wajib + opsi kirim via WA admin.
  • Antrean admin: nominal yang harusnya vs bukti vs tombol Setujui/Tolak + hubungi WA + jejak audit (siapa, kapan, order apa).
  • Auto-batal 1×24 jam supaya antrean tidak menumpuk.
  • Notifikasi HP GoPay merchant sebagai bel pendamping.
  • Kode unik hanya cadangan darurat bila ada 2 nominal sama dalam 1 jam.

4. Skema poin pembeli (perlu keputusan)

  • Usulan: samakan dengan relawan — mis. Rp 10.000 = 25 poin (20.000 = 50 poin). Donatur besar otomatis menuju 20.000 → bisa ajukan proyek. Adil + memotivasi.
  • Alternatif: tanpa poin (pembeli murni bayar). Alternatif 2: poin khusus donasi terpisah (rumit, tidak disarankan).
